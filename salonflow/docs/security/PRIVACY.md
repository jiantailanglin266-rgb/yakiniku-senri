# 個人情報の取り扱い

**本書は法的助言ではありません。** 実装上の取り扱いを記述したものです。
法令適合性の確認は [../legal/LEGAL_REVIEW.md](../legal/LEGAL_REVIEW.md) を参照してください。

---

## 1. 取り扱う情報

| 種別 | 具体例 | 保存先 |
| --- | --- | --- |
| 識別・連絡先 | 氏名、ふりがな、電話番号、メール、郵便番号、住所 | `Customer`, `CustomerAddress` |
| 属性 | 生年月日、性別、職業、来店経路 | `Customer` |
| 行動履歴 | 来店日時、担当者、メニュー、金額、キャンセル回数 | `Appointment`, `Sale` |
| **身体に関する情報** | 髪質、ダメージ状態、肌状態、爪の状態、アレルギー | `MedicalRecord`, `MedicalRecordResponse` |
| **画像** | ビフォーアフター、デザイン写真、署名 | `MedicalRecordPhoto` |
| 同意状況 | 同意種別・取得/撤回日時・取得時 IP / UA | `CustomerConsent` |
| 操作履歴 | 誰がいつ何を見たか | `AuditLog` |

アレルギー情報や肌・爪・髪の状態が「要配慮個人情報」に該当するかは
**専門家の確認が必要**です（LEGAL_REVIEW PI-1, PI-2）。

## 2. 実装している保護

| 対策 | 実装 |
| --- | --- |
| 同意管理 | `CustomerConsent` に種別ごとに記録。取得時 IP / UA も保存 |
| 閲覧の記録 | 顧客詳細・カルテ・写真の閲覧を監査ログへ |
| 項目マスキング | ロール別に電話・メール・金額・写真をサーバー側で落とす |
| CSV へのマスク適用 | 画面で見えない値はファイルにも出ない |
| 写真の保護 | 署名付き短期 URL + セッション/権限の再確認 |
| 秘密情報の非記録 | 監査ログからパスワード・トークン・カード番号を自動除去 |
| 論理削除 | `deletedAt`。物理削除しない |
| 匿名化 | 削除依頼時に識別情報を上書きし `anonymizedAt` を記録 |
| テナント分離 | 他法人からのアクセスを拒否（結合テストで検証） |
| 運営者の制限 | SaaS 運営者ロールはカルテを閲覧できない |

## 3. 同意の種類

`ConsentType` として以下を定義しています。

| 種別 | 用途 |
| --- | --- |
| `terms_of_service` | 利用規約 |
| `privacy_policy` | プライバシーポリシー |
| `marketing_email` | メール配信 |
| `marketing_sms` | SMS 配信 |
| `marketing_line` | LINE 配信 |
| `photo_usage` | 写真の利用 |
| `medical_record` | カルテ情報の取得 |

公開予約フローでは `terms_of_service` と `privacy_policy` を取得し、
取得時の IP / User-Agent を証跡として保存します。

**未実装**: 写真利用の用途別（カルテ保存 / SNS 掲載 / 教育利用）分離、
配信のオプトアウトリンク。

## 4. 保持期間

| データ | 既定 | 状態 |
| --- | --- | --- |
| カルテ | 5 年 | **設定値のみ。自動削除は未実装** |
| 論理削除後の復元可能期間 | 30 日 | **未実装** |
| 監査ログ | プラン依存（90 日〜7 年） | **未実装** |
| セッション | 12 時間（絶対）/ 7 日（アイドル） | 実装済み |
| 冪等キー | 24 時間 | 実装済み（クリーンアップジョブは未実装） |
| 署名付き URL | 300 秒 | 実装済み |

**保持期間の自動削除は Phase 2 の課題です。** 根拠となる期間の妥当性も
専門家の確認が必要です（LEGAL_REVIEW PI-9）。

## 5. 本人の権利への対応

| 権利 | 実装状況 |
| --- | --- |
| 開示 | 顧客詳細画面で確認可。**本人向けのセルフサービス開示は未実装** |
| 訂正 | 顧客編集で対応可 |
| 利用停止 | `marketing_*` 同意の撤回で配信停止 |
| 削除 | `anonymizeCustomer()` で識別情報を上書き |
| データポータビリティ | **未実装**（顧客単位のエクスポートなし） |

### 削除と帳簿保存の衝突

顧客から削除を求められても、会計データには保存義務があります。
本システムは以下の方針を実装しています。

1. `Customer` の識別情報（氏名・連絡先・生年月日・住所・メモ）を上書き
2. `anonymizedAt` と `deletedAt` を記録
3. `CustomerAddress` を削除
4. **`Sale` / `SaleItem` / `Payment` は `customerId` を保持したまま残す**

これにより、会計上は「誰かの取引」として追跡できる一方、
その誰かが特定できない状態になります。

**この方針の妥当性は税理士と弁護士の確認が必要です**（LEGAL_REVIEW PI-8, EB-2）。

## 6. 委託先管理

本システムは、SaaS 提供者がサロン事業者から個人データの取り扱いを
**委託される**構成を想定しています。

設計上の配慮：

- 運営者ロール（`platform_admin`）はカルテを閲覧できない
- テナント間のデータは物理的に同一 DB にあるが、論理的に完全分離
- 運営者の操作もすべて監査ログへ記録

**データ処理契約（DPA）の作成が必要です**（LEGAL_REVIEW DOC-3）。

---

## 7. データ所在地

`DATABASE_URL` と `STORAGE_*` で指定した場所に保存されます。
**Phase 1 では所在地を決定していません。**

越境移転が発生する場合の要件確認が必要です（LEGAL_REVIEW PI-12）。
