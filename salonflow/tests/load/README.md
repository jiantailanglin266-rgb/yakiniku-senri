# 負荷テスト（Phase 2）

Phase 1 では未実装です。本番投入前に以下を計測してください（仕様書 §19, §20）。

| シナリオ | 目標 | 理由 |
| --- | --- | --- |
| 人気時間帯への同時予約 | 予約確定 p95 < 1,500ms、重複ゼロ | 排他制約下での実効スループット |
| 空き枠検索 | p95 < 800ms | 公開ページの体感を決める |
| 予約台帳の表示 | p95 < 500ms | スタッフが一日中開く画面 |
| 一斉通知 | 配送滞留が発生しない件数の上限 | インプロセス実行の限界を知る |
| 大規模 CSV 出力 | 10 万件でメモリが破綻しない | 現在は全件をメモリに載せている |

**特に重要なのは 1 番目**です。排他制約はロック待ちを発生させるため、
同一スタッフの同一時間帯への集中は理論上の直列点になります。
現実のサロン規模でどこまで耐えるかを実測する必要があります。

現在の CSV 出力は全行をメモリ上で組み立てます。
大規模テナントではストリーミングへの変更が必要になる可能性があります。
