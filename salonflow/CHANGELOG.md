## [0.3.0] — 2026-08-04

マスタデータの編集画面。`bootstrap` 直後のテナントを、SQL を書かずに
営業できる状態まで持っていけるようにしました。

### 追加

- 営業時間の編集画面（週 7 日を一括保存、深夜営業は 24:00 超えで表現）
- 店舗情報と予約ルールの編集画面
- メニューの作成・編集・削除画面（放置時間の設定を含む）
- スタッフの作成・編集・削除画面
- シフト編集画面（2 週間分、1 日ずつ独立して保存）
- セットアップ・チェックリスト（営業時間・メニュー・スタッフ・シフトの
  4 項目。すべてそろうまで公開予約ページに空き枠が出ないことを明示）
- 設定系の検証を担う純関数モジュールと 37 件の単体テスト
- 結合テスト 26 件。うち 1 件は「全曜日休業・シフトなしの店舗」から
  実際に空き枠が出るまでを通しで検証します

### 修正

- スタッフ編集の雇用形態から `trainee`（研修生）が抜けていました。
  スキーマの enum を再定義せず参照するよう変更し、再発を防いでいます。

### 備考

- 削除はすべて論理削除です。過去の予約と売上がメニュー・スタッフを
  参照しているため、物理削除は履歴を壊します。
- スタッフを削除しても、そのスタッフに割り当て済みの今後の予約は
  取り消しません。件数を返して担当変更を促します。
- 公開 URL（スラッグ）は編集できません。配布済みのリンクが切れるためです。

## [0.2.0] — 2026-08-04

自前サーバー（Oracle Cloud Always Free 等）での運用に必要なものを実装。

### 追加

- SMTP によるメール送信。465 は暗黙 TLS、587/25 は STARTTLS を必須とします
- `npm run mail:check` — 送信設定の接続・認証確認とテスト送信
- `npm run db:bootstrap` — 実運用の初期テナント作成（デモデータ無し・再実行可能）
- `npm run backup` — ダンプ取得後に `pg_restore --list` で中身を検証
- `npm run build:cli` — 運用 CLI を単一ファイルへバンドル
- docker compose に Caddy（自動 TLS）、通知配送スケジューラ、
  使い捨ての `bootstrap` サービスを追加
- Oracle Cloud Always Free 向けのデプロイ手順書

### 修正

- 本番イメージに `src/` と `tsx` が含まれないため `bootstrap` が実行できませんでした。
  CLI をビルド時に `dist/cli/*.mjs` へバンドルするよう変更しています。
- リポジトリ直下の `.gitignore` の `.env*` が `.env.production.example` まで
  無視していました。手順書の最初のコマンドが成立しない状態でした。

### 備考

- Vercel の Hobby プランは商用利用を許可していません。クライアント提供では
  自前サーバーか有料プランを選んでください（DEPLOYMENT.md §2）。

## [0.1.0] — 2026-08-03

Phase 1（MVP）の初回リリース。

### 追加

#### 基盤

- Next.js 16 / TypeScript / Tailwind CSS v4 / Prisma 6 / PostgreSQL 16 のアプリケーション基盤
- 63 モデルのデータベーススキーマと初回マイグレーション
- `btree_gist` による GiST 排他制約（重複予約防止）
- CHECK 制約（時間区間、回数券残数、ポイント残高、在庫数、評価値）
- 空き枠検索用の部分インデックス

#### 認証・認可

- メール + パスワード認証（scrypt、NFKC 正規化、定数時間比較）
- DB セッション（トークンは SHA-256 で保存、生値は Cookie のみ）
- ログイン失敗によるアカウントロック、IP 単位のレート制限
- ユーザー列挙対策（存在しないアドレスでもハッシュ計算を実施）
- 17 権限・10 ロールの RBAC と店舗スコープ
- 項目単位マスキング（電話・メール・金額・カルテ写真・給与）
- テナントスコープの強制と越境検知テスト

#### 予約

- 純関数の空き枠計算エンジン（区間代数・占有計画・空き枠探索）
- 工程分割対応（放置時間中にスタッフのみ解放し、設備は保持）
- 準備時間・片付け時間・店舗バッファ・スタッフ別所要時間係数
- 営業時間・中休み・定休日・臨時休業・特別営業時間
- 受付締切・最短予約時間・最大予約可能日
- トランザクション内での確定直前再検証
- 冪等キーによる二重送信防止
- 予約状態マシン（7 状態、遷移表で一元管理）
- 予約台帳（日 / 3 日 / 週、スタッフ別列、工程ギャップの可視化）
- ブロック時間・休憩の登録（排他制約で保護）
- 予約の時間変更・担当変更

#### 顧客・カルテ

- 顧客一覧・検索（正規化済み電話/メール/かなでの照合）
- 重複候補の検出と統合（履歴のスナップショット保存）
- 削除依頼への対応（識別情報の匿名化、会計行は保持）
- 業種別カルテテンプレート（ヘア / ネイル / アイ / エステ）
- 動的フィールド（テーブル定義ではなくレコードで表現）
- カルテ閲覧・写真表示の監査記録

#### 通知

- Outbox パターン（予約と同一トランザクションでキュー投入）
- idempotency key による二重送信防止
- 指数バックオフによる再送（最大 5 回）
- 多言語テンプレート（組織 / 店舗 / イベント / チャネル / ロケール別）

#### 公開予約

- `/booking/[storeSlug]` の 6 ステップフロー
- 空き枠のリアルタイム取得（no-store）
- 既存顧客の照合と再利用（正規化した連絡先のみで照合）
- 同意取得（利用規約・キャンセルポリシー・個人情報）
- 即時予約制 / 予約リクエスト制の切り替え

#### その他

- ダッシュボード（当日指標、稼働率、30 日推移、経路別、メニュー別）
- 監査ログの記録と閲覧画面、秘密情報の自動除去
- 署名付き URL によるカルテ写真の保護（署名 + セッション + 権限の三重確認）
- 顧客 CSV 出力（CSV インジェクション対策、マスク適用、監査記録）
- 多言語（日本語 / 英語、管理画面と予約画面を分離）
- セキュリティヘッダ（CSP / HSTS / Permissions-Policy ほか）
- クロスオリジン state 変更の拒否（`proxy.ts`）
- 構造化ログ（秘密情報の自動除去）
- 架空のデモデータ（店舗 2 / スタッフ 6 / 顧客 50 / メニュー 20 / 予約 100 / カルテ 30 / 会計 50 / 商品 10）
- テスト 183 件（単体 153 / 結合 30）
- ドキュメント一式（設計・API・セキュリティ・運用・法務確認項目・ADR）

### 既知の制約

- MFA / パスキー / OAuth 未実装（Phase 2）
- ジョブ実行がインプロセス（複数インスタンスでは Redis が必要）
- レート制限がプロセスメモリ内
- CSP に `'unsafe-inline'` が残存
- 保存データの暗号化なし
- データ保持期間の自動削除なし
- POS / 会計 UI・在庫・クーポン・ポイント・回数券・月額会員は未実装
- 店舗・スタッフ・メニューの編集画面は未実装（閲覧のみ）
- メール送信は開発用トランスポートのみ（実送信しない）

### 法務

- 商標調査、プライバシーポリシー、利用規約、DPA は未作成
- 消費税の端数処理、適格請求書の記載事項は税理士確認が必要
- 回数券・ポイントの資金決済法該当性は未確認のため販売機能を実装していない
- 労務管理（打刻・勤怠）は社労士確認が必要なため未実装
