# サイト構造・内部リンク設計とブログ100本｜焼肉 千里

---

## 1. 現状の構造（実装を読み取ったもの）

```
/                     TOP
├── /about            当店について
├── /commitment       こだわり
├── /menu             お品書き（15カテゴリー定義・18品目実在）
├── /takeout          テイクアウト
├── /owner            オーナー紹介
├── /news             お知らせ
│   └── /news/[slug]  記事（3本）
├── /access           アクセス・店舗情報（FAQ設置）
├── /contact          お問い合わせ
├── /sitemap          サイトマップ
└── 法的ページ        /privacy /cookie /terms /notes /legal
```

### ■問題点

1. **部位別・シーン別の受け皿がない。** 主軸「世田谷 焼肉」以外のロングテールを取りにいくページが物理的に存在しない
2. **ブログがない。** Know意図の検索を1本も拾えていない
3. **地域ページがない。** 「三軒茶屋 焼肉」等で上位を狙う導線がゼロ
4. **お知らせ本文が全件プレースホルダー。** 3記事すべて `[本文をここに入力してください]`。**インデックスされると低品質判定のリスク**
5. **内部リンクが階層的で、横のつながりが薄い**（メニュー→こだわり→オーナーの相互リンクがない）

### ■改善理由

Googleは「1ページ＝1検索意図」を基本に評価します。18品目を1ページに載せた `/menu` は、
「もみタン」「石焼チーズフォンデュ」といった個別KWでは他サイトに勝てません。
AI検索（ChatGPT / Perplexity）も、**明確な見出しと1トピック1ページ**の構造から引用します。

> **/area の注意**：中身のない地域ページを量産すると「ドアウェイページ」としてペナルティ対象になります。
> 各ページに**そのエリア固有の情報**（実際の道順・所要時間・目印・バス便・駐車の可否）を必ず入れてください。
> 書けない地域は作らないでください。4ページで十分です。

## 3. 内部リンク設計

### 3-1. リンクの原則

| 原則             | 内容                                                     |
| ---------------- | -------------------------------------------------------- |
| ハブ&スポーク    | `/menu` がハブ。各部位ページから必ずハブへ戻す           |
| 3クリック以内    | TOPからどのページへも3クリック以内                       |
| CVへ集約         | 全ページから `/contact`（電話）へ1クリック               |
| アンカーテキスト | 「こちら」禁止。「もみシリーズの詳細」のようにKWを含める |
| 相互リンク       | 関連の深いページ同士は双方向で結ぶ                       |

### 3-2. 主要導線

```
TOP
 ├→ /menu（お品書きを見る）           ← 既存CTA
 ├→ /contact（電話で予約する）        ← 既存CTA
 ├→ /access（アクセスを見る）          ← 既存CTA
 └→ /menu/momi（名物もみシリーズ）     ← 新規追加推奨

/menu   → /menu/momi /menu/beef /menu/hormone /menu/single /menu/drink
/menu/momi → /commitment（秘伝のタレ）→ /about（歴史）→ /owner（三代目）→ /menu/momi
        ↑ この4ページの循環がE-E-A-Tの核。必ず双方向で結ぶ

/blog/[記事] → 関連記事2本 + 該当メニューページ + /contact
/area/[駅]   → /access（詳細地図）+ /contact
全ページ     → /faq → /contact
```

### 3-3. 実装済みの土台

- パンくず（`Breadcrumbs.tsx` + `BreadcrumbList` JSON-LD）
- フッター全ページリンク
- `RelatedLinks.tsx`（下層ページの関連リンク枠）
- モバイル固定バー（電話・地図・お品書き）

## 4. ブログ100本設計

### 方針

- **1記事1KW**。狙うKWをtitleとH1に必ず含める
- **結論ファースト**。冒頭150字で答えを書く（AI検索の引用対象になる）
- 全記事に**内部リンク3本以上**（関連記事2＋CVページ1）
- 実店舗の一次情報（写真・実際の会話・仕込みの様子）を必ず含める＝E-E-A-T

### 実装の優先順位

```
最優先（先に10本）  1, 2, 3, 5, 13, 14, 23, 24, 33, 47
                    → 独自性が高く、かつ検索需要がある
次（20本）          カテゴリA残り + カテゴリB前半
その後              カテゴリC（地域）を月4本ペース
```

**月4本を1年継続**が現実的な目標です。100本を一気に作ると品質が落ち、
薄いページ量産としてマイナス評価になります。
