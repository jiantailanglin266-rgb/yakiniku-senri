# SPORTS PORT — 設計方針・サイトマップ・導線

このリポジトリには4つのサイトが同居しています。

| サイト      | URL                                      | ルート                          |
| ----------- | ---------------------------------------- | ------------------------------- |
| 焼肉 千里   | `/`, `/menu`, `/news` …                  | `src/app/(senri)/`              |
| AI PORT     | `/ai-port/…`                             | `src/app/ai-port/`              |
| CRYPTO PORT | `/ja/`, `/en/` …                         | `src/app/(portal)/[locale]/`    |
| SPORTS PORT | `/sports-port/ja/`, `/sports-port/en/` … | `src/app/sports-port/[locale]/` |

ルートレイアウト（`src/app/layout.tsx`）は `<html>` / `<body>` だけを持ち、
ブランド固有の外枠（背景・ヘッダー・フッター・フォント・CSS）は各サイトのレイアウトにあります。
SPORTS PORT の CSS は `.sports-root` 配下に閉じており、他サイトへは配信されません。

### なぜ `/sports-port/` 配下なのか

ルートの `/{locale}/` は CRYPTO PORT が使用しています。
同じ階層に `[locale]` を2つ置くと同一URLへ解決してビルドが通らないため、前置パスを付けています。
値は `src/sports/config/site.ts` の `brand.routePrefix` 1か所で管理しており、
独自ドメインへ切り出すときは空文字にすれば `/ja/` に戻ります。

## 1. 設計方針

### 1.1 いちばん優先したこと

**スコアと時刻が、どんな装飾よりも先に読めること。**

未来的な見た目は目的ではなく手段です。次の3点をこの順で守っています。

1. **可読性** — スコア・チーム名・開始時刻は必ず不透明な面（`sp-solid`）の上に置く。装飾は背景レイヤーに閉じ込める
2. **正直さ** — 取得時刻・更新間隔・情報元を必ず添える。取得に失敗したら古い値を「最新」として出さない
3. **速さ** — 主役はデータなので、初期表示を遅らせる演出は採用しない

### 1.2 データを起点にした設計

「競技を1つ増やす」ときに変更するのは `src/sports/data/sports.ts` の**1件のオブジェクトだけ**です。

- 順位表の列 → `Sport.standingsColumns`
- 試合スタッツの項目 → `Sport.statKeys`
- 試合の区切り方（ハーフ / イニング / セット / ラウンド / マップ） → `Sport.periodType`
- 引き分けの有無 → `Sport.hasDraw`

順位表コンポーネント・スコアボード・スタッツバーはすべてこの設定を読むだけなので、コンポーネントの改修は発生しません。
テスト（`tests/sports-data.test.ts`）が、順位表の値と競技の列定義が一致していることを検証します。

### 1.3 事実性のルール

| ルール                                            | 実装                                                 |
| ------------------------------------------------- | ---------------------------------------------------- |
| 未確認の情報を載せない                            | 収容人数・設立年など裏取りできない項目は空のまま     |
| 実在の選手に架空の成績を結び付けない              | デモの選手名はすべて架空                             |
| 実在の配信事業者に誤った料金を載せない            | サービス名はすべて架空。URL は `example.com`         |
| 評価の実体がないのに `AggregateRating` を出さない | 構造化データから除外（テストで検証）                 |
| デモデータであることを隠さない                    | 全ページ上部にバナー、各パネルに `provenance` バッジ |

## 4. ユーザー導線

```
                       ┌──────────────┐
   検索 / SNS / YouTube │ ファーストビュー │
                       └───────┬──────┘
        ┌──────────────────────┼──────────────────────┐
        ▼                      ▼                      ▼
  ライブスコア            今日の試合              診断（競技/配信）
        │                      │                      │
        ▼                      ▼                      ▼
    試合詳細 ──────────► 視聴方法（配信比較）◄──── 診断結果
        │                      │
        ├─► チーム詳細 ─► グッズ / チケット
        ├─► 選手詳細
        ├─► 関連ニュース ─► 関連動画
        └─► リーグ詳細 ─► 順位表
```

**収益地点は「意思決定の直後」に置く**という原則にしています。
配信サービスへの導線は、試合詳細・リーグ詳細・診断結果・動画詳細——つまり
「この試合が見たい」と決まった直後にだけ出します。トップページに散らしません。
