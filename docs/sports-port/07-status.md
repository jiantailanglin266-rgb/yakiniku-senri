## 3. 既知の問題・注意点

### デモデータの基準日

デモの試合日程は**ビルド日を基準**に組み立てています（`src/sports/data/clock.ts`）。
デプロイした日の「今日」が正しく表示されますが、**再ビルドしない限り日付は進みません**。
表示中のデータには常に取得時刻が添えられているため、古さは画面上で判別できます。

### 静的書き出しでの `/api/sports/live`

GitHub Pages ではビルド時点のスナップショットが静的JSONとして書き出されます。
ライブティッカーはこれを取得しますが値は変化しません（デモデータなので元々変化しません）。
取得に失敗した場合は「更新できていません」と表示され、古い値を最新として見せることはありません。

### 検索の `?q=`

静的書き出しではサーバー側で `searchParams` を読めないため、
`?q=` はハイドレーション後にクライアント側で反映されます（`Suspense` 境界あり）。
外部からの検索リンクは動作しますが、初回描画には含まれません。

### 選手データ

デモの選手はすべて**架空**です。実在の選手に架空の成績・移籍・負傷情報を結び付けないための措置で、
バグではありません。実APIに接続すると実在の選手データに置き換わります。

### 配信サービス

サービス名はすべて架空、URLは `example.com`（ドキュメント用予約ドメイン）です。
実在サービスに誤った料金を掲載しないための措置です。
